# 动作采集工作台设计

状态：用户已批准。电脑端采集工作台已实现，使用浏览器界面和仅监听本机的 Python 服务，默认静音。

目的：在电脑上采集或导入单人视频，人工标注动作，生成供后续训练和 Android 规则接入使用的材料。本地保存，默认静音，预览中所有数字与数据均为示例。

流程：采集与导入 → 片段标注 → 数据检查与导出。

- 采集：摄像头录制或导入视频，填写动作、匿名拍摄者编号、角度与节奏，提示采集授权。站立、走动等设为“其他行为”。
- 标注：人工设定动作类型及起止时间，可选填写真实次数、遮挡及备注。原始视频、人工标签和自动推理结果分开保存；识别失败、遮挡和未知动作不能自动标成有效动作。
- 提取：利用姿态模型为每帧保存输入视频时间戳、坐标、置信度、缺失标记、模型版本、坐标体系和采样配置；原画面不拉伸，关节点与显示画面保持一致。ML Kit Android 路径不可假定直接能在电脑 Python 上运行，具体电脑端提取器及其与 Android 端预处理一致性需实现前验证。
- 检查：显示缺少标签、损坏视频、无效时间区间、采样中断、关键点缺失和待复核片段；不将模型置信度当成准确率。训练/验证/测试按拍摄者编号分组，组间隔离；保留划分结果、随机种子及数据版本。人不足或未知时标明无法可靠划分，不伪造验证指标。
- 导出：训练数据包包含可追溯的标签、关节点、时间戳、数据划分及处理版本，可选附带原始视频；数据包不等于训练后的模型。单独的 Android 动作规则配置包含动作、关节点、角度阈值和版本；Android 仍需对应规则执行器。未来如训练模型，需单独导出可部署格式并验证移动端输入一致性和性能。
- 界面截图中的照片为项目内置视频静帧，非摄像头实时画面；交互预览不读写实际视频或数据。

验收需覆盖：导入与录制、区间校验、手动标注、不完整关键点、拍摄者划分隔离、数据包导出和读取、隐私与来源、静音。该设计为桌面工具，既不打包 APK，也不连接设备。

## 当前实现与验证

入口为 `tools/motion_collection/collector.py`。浏览器录制仅请求视频，不采集声音；导入支持 MP4、MOV、M4V、WebM，录制为 WebM。数据默认存放在工具目录的 `data/`，不加入 Git。标注需要人工确认，提取使用项目已有的 RTMPose-t ONNX，生成 COCO-17 归一化坐标、缺失标记和来源版本。每段单独提取，修改标注后须重新提取；导出排除未确认或未提取的样本，阻止同一个视频归入不同拍摄者，按拍摄者分组并提示集合内缺失类别。

电脑提取遵循项目现有 Android RTMPose 的整帧缩放和归一化参数，但电脑 OpenCV 和 Android Canvas 的插值与解码可能存在差异，尚未做同帧逐点比较，不能声称输出完全一致；模型置信度不是准确率。OpenCV 对缺少可靠时间戳的帧使用帧序号除帧率回退，因此可变帧率素材需要另行核对时序。缺失关节点保留为空并显示数量，需人工检查。当前每个视频保存一个人工片段，长视频多片段需拆分或后续扩展。

已通过本地 Python 流程测试（标注边界、真实模型推理、按人划分、导出、重复视频检查等），并用真实样片和模拟摄像头验证网页导入、标注、提取及录制。未使用真实摄像头或 Android 设备，真实摄像头及浏览器编解码兼容性仍需实际验证。
