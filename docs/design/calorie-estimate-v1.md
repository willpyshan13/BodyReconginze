# 训练热量估算设计

状态：用户已明确批准并实现。训练页使用最终确认的“热量消耗（估算）”顶部卡片；新增界面尚未实机验证。保持静音，不打包 APK、不连接设备。

## 目的与范围

让摄像头本人训练有一个可解释的消耗参考，沿用现有暖白、深绿界面。第一版离线计算，不增加账号、联网服务、心率设备或语音。训练设置 → 摄像头训练 → 结束总结 → 本人记录构成完整流程；内置及导入视频仍是视频人物分析，不生成本人的热量数据。

## 界面与状态

- 训练设置增加可选体重输入，单位 kg，支持一位小数；本地记住，允许修改或清除。未填写仍可训练，消耗显示“— / 未填写体重”。不擅自使用默认体重。设计稿中的 60 kg 为明确标记的示例值。
- 摄像头训练在动作标题下、取景画面上方显示“热量消耗（估算）”，打开预览即展示该区域，避免被设置页或下方内容遮住。点击“查看依据”展开本次体重、参考强度与参与估算的时长。显示千卡、小于 0.1 千卡时显示“<0.1”，不暗示小数位代表测量精度。
- 暂停、休息、倒计时、对齐准备、无可靠姿态时，按现有有效计时逻辑停止累计；保留已估算结果。恢复后继续。第一版不按动作次数固定换算，也不从关节角、速度、模型置信度推断实际代谢强度。
- 结束总结和本人历史记录显示本次估算值及依据；每次开始时固定体重和参考类别，后续修改体重不重算既有记录。
- 视频模式在相同区域明确显示“视频分析 / 不计入个人消耗”，隐藏个人数值；视频记录保留来源标记。
- 旧记录缺少热量字段时显示“未估算”，不用 0 代替缺失值。用户未填写体重同样保留缺失原因。

## 计算口径

采用有效训练时段的总能耗估算：

`kcal = MET × 3.5 × weightKg / 200 × activeMs / 60000`

数值包含参与估算时段的静息消耗，排除未参与计时的休息/暂停时段；不将它称为扣除静息后的“额外活动消耗”。界面固定标“估算”，依据说明中写明“有效训练时段总消耗，含静息消耗”。

动作采用明确可追溯的参考类别，第一版固定普通强度，不把强度称为摄像头实测值：深蹲、俯卧撑参考 2024 Compendium 02056 普通徒手抗阻训练 3.0 MET；哑铃弯举、侧平举参考 02054 普通多动作抗阻训练 3.5 MET，属于类别近似；双臂上举参考 02030 普通轻中强度徒手操 3.5 MET，属于类别近似。后三项并非各个单动作的独立测量值，说明中需呈现类别近似。新增动作没有适用的参考类别时显示“暂无估算依据”，不随意填值。不能从画面判断是否持有哑铃、负重或实际主观强度。

现有有效训练计时依据训练状态及近期可靠姿态，并不能证明全程持续用力；组内静止、实际负重和个体代谢差异都会影响误差，不能宣称已经测得实际能量消耗。

## 示例与验收

预览照片取自现有内置视频静帧，仅作取景示意。全部组次、时长和消耗均为设计样例，未运行模型或采集个人数据。

预览采用普通徒手深蹲、60 kg：训练中有效时长 18 秒对应 0.945 千卡，显示约 0.9 千卡；结束时有效时长 80 秒对应 4.2 千卡。体重输入、跳过、暂停/恢复、视频模式、结束总结和记录导航可交互。

## 实现与验证

- `TrainingCalories.kt` 使用不可变的会话依据计算，按动作名称映射参考类别，保留未四舍五入的结果、方法版本、参考条目及缺失原因。展示一位小数；正值不足0.1千卡时显示“<0.1”。
- `CoachActivity.kt` 加入本地可选体重输入（20–300 kg，一位小数）及跳过入口；新安装不填默认值。训练标题下、取景上方显示热量卡片并可展开依据；结束总结和单次记录均展示热量。内置及导入视频共用视频排除逻辑，记录中不写入个人体重或热量。
- 新记录在 `calorieEstimate` 中保存快照，历史读取不使用当前体重或重查当前MET表；旧记录与缺少完整依据的记录显示未估算。
- 本地文字对话支持热量、卡路里、热耗、千卡和消耗问题，引用本次估算及依据，不再将“消耗多少”误识别为询问动作次数；无依据时明确说明。
- 已通过 JDK 17 / Android SDK 下的 `./gradlew :demo-android:testDebugUnitTest --offline`，包含计算与输入、准备/休息/暂停/识别缺失时的累计边界、视频排除、历史兼容、会话依据固定及对话回归。仅有既存 Android API 弃用警告。
- 未打包APK，未安装或启动应用，未连接设备；实际触屏显示与摄像头训练仍待后续设备验证。测试验证计算和流程边界，不证明个体热量估算准确度。
